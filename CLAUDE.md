# Домашний роутер — рабочая папка для агентов

Здесь всё, что нужно, чтобы обслуживать домашний роутер пользователя: документация, снимок настроек
и бэкапы. **Сам роутер — источник правды**; `mirror/` — только снимок для чтения.

Пользователь пишет по-русски и на «ты», отвечай так же.

## Что это за роутер (коротко)

- **Xiaomi AX3000T** (MT7981, arm64, 2 ядра, 234 MB RAM + 150 MB zram), **OpenWrt 25.12.2**, пакеты через `apk`.
- Время на роутере **московское** (MSK-3, с 2026-10-04 21:38; раньше было UTC — старые записи в history.md
  помечены UTC). Журналы, cron и отчёты — по Москве.
- Стоит **за роутером провайдера** (двойной NAT): WAN `WAN_IP` ← `UPSTREAM_IP`; LAN `LAN_IP/24`. Тариф 100 Мбит.
- **sing-box 1.13** в режиме TUN (`tun0`): **всё российское — напрямую, всё остальное — через VPN** (схема A).
- VPN — две подписки VLESS + Reality: **P1-** (основной провайдер, 25 нод в ЕС) и **P2-** (запасной провайдер, 13 нод).
- DNS раздельный, внутри sing-box: российские домены → Яндекс напрямую, остальные → Cloudflare DoH через VPN.
- Tailscale на самом роутере — удалённый доступ (главное — стабильность) и exit node; свой сторож `ts-watchdog.sh`.
  Настройки менять только `tailscale set`, никаких `up --reset` и перезапусков при загрузке.

Подробно: [docs/architecture.md](docs/architecture.md). Типовые задачи: [docs/runbook.md](docs/runbook.md).
Почему всё устроено именно так: [docs/history.md](docs/history.md).

## Доступ

```
ssh openwrt-ts   # через Tailscale (TS_IP) — работает откуда угодно
ssh openwrt      # из дома по LAN (LAN_IP)
```
Ключ `~/.ssh/openwrt_claude` (выдан агенту, отзывается в `/etc/dropbear/authorized_keys` на роутере).
Tailscale-трафик роутера идёт **мимо sing-box** (fwmark 0x80000 → ip rule 5210), поэтому `ssh openwrt-ts`
переживает перезапуски и падения sing-box. Пользователь часто **не дома** — проверяй всё с самого роутера.

## Золотые правила

1. **Сначала спроси, потом меняй.** Пользователь просил не «рубить с плеча»: неясно, зачем что-то сделано
   или есть выбор — опиши варианты и спроси. Ошибка = у семьи пропадает интернет.
2. **Перезапуск sing-box — только `/usr/bin/sb-restart.sh` (просто перезапуск) или `/usr/bin/apply-vless.sh --force`
   (после правки конфига: ещё проверит туннель и запомнит конфиг как рабочий).** Никогда `/etc/init.d/sing-box
   restart`/`reload`: быстрый перезапуск однажды сломал LAN. Учти: если после apply-vless связи нет, он откатывает
   конфиг, а если ноды живы, но трафик не идёт — делает `network restart` и в крайнем случае перезагрузку (≤1 раз в 6 ч).
   Вся автоматика построена на `/usr/lib/sb-common.sh` — новые скрипты подключай его же, проверки бери оттуда.
3. **Любую правку конфига — сначала на копии:** `sing-box check -c <копия>`; для DNS/маршрутизации —
   временный экземпляр sing-box без TUN на другом порту (пример в runbook). Перед изменениями — бэкап на Mac
   (`./scripts/pull-from-router.sh` или папка в `backups/<дата-событие>/`).
4. **Не запускай ничего тяжёлого около :07 и :37 каждого часа** — в это время cron запускает `apply-vless.sh`.
   Все скрипты делят блокировку `/tmp/apply-vless.lock`.
5. **На роутере не больше двух бэкапов** — правило пользователя: `/root/backups` (2), для конфига sing-box —
   один `config.json.bak.*` + `config.json.good` (последний рабочий, нужен автоматике — не удалять).
6. **Решения пользователя, не пересматривать без запроса:** схема A (а не «напрямую по умолчанию»);
   Google идёт через `auto`, не принудительно через P1; flow offloading (программный) включён;
   теги нод из подписок не трогать.
7. **Секреты.** В `mirror/` и `backups/` лежат ссылки подписок, UUID нод, ключи. Никуда не публиковать,
   не пушить, не печатать в чат ссылки подписок и `.clash-secret`. Публичная копия на GitHub обновляется
   только через `python3 publish/publish.py --push` — руками в `.public/` ничего не класть.
8. **busybox:** нет `nohup`, `diff`, `install`, `find -delete`, `flock -w` → фоновый запуск через
   `setsid sh script &`, сравнение — на Mac, ожидание блокировки — `lock_wait` из sb-common.sh.
   Нет `timeout` → `cmd & sleep N; kill $!`. Сложный python/шелл с кавычками — пиши файлом и `scp -O`;
   tar с Mac — с `COPYFILE_DISABLE=1`, иначе на роутер приедут файлы `._*`.
9. **Тесты, которые трогают живой sing-box, имеют побочные эффекты:** неудачная проверка ноды через
   `/proxies/<нода>/delay` стирает её историю, и группа перестаёт её выбирать до следующей проверки.
   Пробный прогон сторожа на копии: функции, которые скрипт объявляет сам (`restart_safely`, `refresh`), заглушкой
   до них не подменить — скрипт переопределит её своей. 2026-10-04 так случился лишний перезапуск. Вырезай такие
   функции sed'ом или переименовывай; `providers_ok` делает настоящие проверки нод.
10. **Массовый `apk upgrade` не делать** (на 2026-10-03 ждут 101 пакет базовой системы). sing-box и tailscale
    закреплены в `/etc/apk/world` как `sing-box~1.13`, `tailscale~1.98`; обновление — по runbook.

## Где что лежит

| Путь | Что |
|---|---|
| `mirror/` | Снимок файлов с роутера (пути как на роутере) + `STATE.txt` (версии, память, ip rule). Обновить: `./scripts/pull-from-router.sh` |
| `backups/auto/` | Два последних полных бэкапа `sysupgrade -b` (восстанавливаются через LuCI) |
| `backups/<дата-событие>/` | Памятные точки отката: утро до изменений, перед миграцией DNS (там же бинарник sing-box 1.12.17), архив удалённого мусора |
| `docs/` | Архитектура, runbook, история решений |
| `publish/` | Публичная копия на GitHub ([nkkalmyk/openwrt-singbox-router](https://github.com/nkkalmyk/openwrt-singbox-router)): `publish.py` собирает очищенную копию в `.public/` и не пускает её дальше, если нашёл IP, MAC, ключи или слова из `private.txt` (личные замены, сам не публикуется). Без `--push` — только собрать и проверить. Новое личное в docs (адрес, имя, провайдер) — добавь правило в `private.txt` |
| `.public/` | Git-клон публичного репозитория, генерируется `publish.py` — не править |

Главные файлы на роутере: `/etc/sing-box/config.json`, `/etc/sing-box/rule-set/my-*.json` (ручные списки),
скрипты в `/usr/bin/` (`apply-vless.sh`, `update-vless.py`, `sb-watchdog.sh`, `sb-ping`, …), cron `/etc/crontabs/root`.

## Быстрая диагностика

У пользователя для ручной работы — команда `vpn` (`/usr/bin/vpn`, обёртка над всем ниже; `vpn help`).
Предлагай ему её, а не длинные пути. Новые ручные действия добавляй подкомандами туда же.
```
ssh openwrt-ts 'vpn'                          # сводка: интернет, VPN, sing-box, Tailscale, события
ssh openwrt-ts 'vpn report 24'                # отчёт за N часов с итогом (сам пишется 2×/день в /root/reports.log)
ssh openwrt-ts 'sb-ping'                      # ноды, задержки, что выбрано
ssh openwrt-ts 'sb-ping route ozon.ru'        # куда пойдёт сайт и по какому правилу
ssh openwrt-ts 'tail -5 /tmp/health.log'      # память, conntrack, sb=RSS, proxy/direct каждые 5 мин
ssh openwrt-ts 'sb-ping events'               # что делала автоматика (постоянный журнал, переживает перезагрузку)
ssh openwrt-ts 'logread -e sb-watchdog -e apply-vless -e sb-restart | tail -20'
```
Устойчивость системы разобрана в [docs/resilience-audit.md](docs/resilience-audit.md) — что уже закрыто и как проверено.

## Открытые вопросы (на 2026-10-03)

- Память: смотреть `RssAnon`, а не VmRSS (подробно — architecture.md, «Память»). sing-box ~15 MB своих при
  лимите 45 MiB — проблемы нет. Тревожно, если `sb=` в health.log растёт часами или MemAvailable < 40 MB.
- Понаблюдать `sb-ping events` после ближайших сбоев: автоматика устойчивости внедрена 2026-10-03 ~13:05.
  Первые сутки прошли нормально. 2026-10-04 P1 сменил адреса, и VPN не работал ~19 мин. После этого сторож
  на 3-й мин без VPN обновляет подписки, а cron проверяет их раз в 30 мин. Посмотреть, как это сработает при
  следующей смене адресов (`vpn report`). Ещё не решено: перепроверять ноды на 1-й мин вместо 2-й и обновлять
  подписки, когда мертва половина P1.
- Тестовая виртуалка удалена 2026-10-04 (вместе с образом и тестовым ключом). Как собрать заново — history.md,
  2026-10-04 ~16:40. В `docs/setup.md` не проверены Tailscale и две подписки. Два старых коммита
  (`b355f8c`, `1dd4270`) ещё открываются на GitHub по хешу; там нет секретов, только города нод — пользователь
  решил оставить.
- Exit node роутера объявлен, но **ждёт одобрения в админке Tailscale** (делает пользователь). После — проверить
  с телефона (runbook, раздел Tailscale).
- Tailscale переделан на стабильность 2026-10-03 (без перезапусков при загрузке, свой сторож) — понаблюдать
  `logread -e ts-watchdog` после ближайшей перезагрузки.

После заметных изменений на роутере: обнови `docs/` (особенно history.md) и сними `./scripts/pull-from-router.sh`.
