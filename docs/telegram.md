# Роутер в Telegram: уведомления и команды

Роутер сам пишет в Telegram, когда что-то сломалось и когда починилось. Тому же боту можно отправлять команды:
посмотреть состояние, ноды, куда идёт сайт, перезапустить sing-box или весь роутер. Работает откуда угодно:
роутер сам опрашивает Telegram, поэтому белый IP, проброс портов и VPN до дома не нужны.

Всё делает один скрипт [router-notify](../mirror/usr/bin/router-notify) (busybox `sh` + `curl` + `jq`) и служба
[init.d/router-bot](../mirror/etc/init.d/router-bot). Отдельный сервер не нужен.

## Подключение (3 минуты)

1. **Создай бота.** В Telegram открой [@BotFather](https://t.me/BotFather), отправь `/newbot`, придумай имя и адрес
   на `bot` (например, `my_home_router_bot`). BotFather пришлёт токен вида `123456789:AAH…`.
2. **Подключи бота на роутере** — по SSH:
   ```sh
   vpn tg setup
   ```
   Вставь токен, затем открой бота по ссылке, которую покажет скрипт, нажми «Старт» и вернись в терминал (Enter).
   Скрипт сам узнает твой chat id и пришлёт «✅ Роутер подключён» со списком команд.

Токен лучше вводить самому на роутере, а не пересылать кому-то (в том числе ИИ-агенту). Он хранится в
`/etc/router-notify.conf` (права `600`); этот файл есть в `sysupgrade.conf`, поэтому переживёт обновление прошивки.

## Что присылает

| Сообщение | Когда |
|---|---|
| 🔴 VPN не работает уже 10 мин… | автоматика не справилась за 10 минут (короткие сбои, которые сторож чинит сам, не присылаются) |
| ✅ VPN снова работает. Не работал ~N мин | после 🔴, когда связь вернулась |
| 🌐 У провайдера не было интернета N мин: с … до … | интернет у провайдера пропадал больше чем на 5 минут (приходит, когда он вернулся) |
| 🔄 Роутер перезагрузился… | после любой перезагрузки: примерно сколько был выключен и почему — автоперезагрузка, команда из Telegram или пропадало питание |
| ⚠️ … | серьёзные события автоматики: откат конфига, sing-box упал, Tailscale требует входа и т. п. Одно и то же — не чаще раза в час |

Если в момент проблемы Telegram недоступен (например, лёг VPN), сообщение ждёт в очереди и уходит позже. Отправка
сначала идёт обычным путём, через VPN, а если не получилось — напрямую через провайдера.

## Кнопки и команды

Под полем ввода — постоянные кнопки: **📊 Состояние · 🌐 Ноды · 📅 Сутки · 📋 Отчёт · 📜 Журнал · ⚙️ Ещё**. Нажатие работает как команда.
«⚙️ Ещё» открывает кнопки в сообщении: обновить ноды, автовыбор, скорость, перезапуск, перезагрузка.
`/restart` и `/reboot` спрашивают подтверждение кнопками **✅ Да / ✖️ Отмена**: после нажатия вопрос заменяется текстом, кнопки
пропадают, повторное нажатие ничего не делает.

| Команда | Что делает |
|---|---|
| `/status` | состояние: интернет, VPN (страна выхода и нода), sing-box, Tailscale, последние события; сверху вердикт 🟢 / 🟡 / 🔴 |
| `/nodes` | лучшие ноды с задержками (🟢🟡🔴), что выбрано сейчас, мёртвые |
| `/gemini` | ноды для Gemini |
| `/day` | сегодня и вчера по часам: где были сбои VPN и интернета у провайдера |
| `/week` | последние 7 дней, по короткой строке на день |
| `/report` | отчёт о здоровье за 12 часов |
| `/log` | что делала автоматика, по датам |
| `/site ozon.ru` | куда идёт сайт — напрямую или через VPN — и почему |
| `/auto` | вернуть автовыбор ноды |
| `/update` | обновить ноды из подписок |
| `/speed` | замер скорости через VPN и напрямую (~1 мин) |
| `/restart` | перезапустить sing-box (~6 с без интернета), с подтверждением |
| `/reboot` | перезагрузить роутер (~2 мин без интернета), с подтверждением |
| `/more` | меню кнопок «Ещё» |
| `/help` | список команд |

Меню команд появляется по кнопке «/» слева от поля ввода.

### Как выглядят ответы

Ответы рассчитаны на узкий экран телефона: короткие строки, значки вместо слов «OK/НЕТ», без таблиц, флаги стран (в Telegram они
рисуются, в некоторых терминалах нет). Их делает [router-tg](../mirror/usr/bin/router-tg): берёт вывод обычных команд (`vpn status`,
`sb-ping`, `router-report`…) и переписывает; терминальный вывод не меняется. Если формат команды изменится и разбор сломается,
бот пришлёт исходный текст, а не промолчит.

`/day` — одна сетка по 8 часов в строке (ночь, день, вечер), один квадрат = час:

```
📅 Вчера, 4 октября
00  ⬛⬛⬛🟩🟩🟩🟩🟩
08  🟨🟩🟩🟩🟥🟩🟩🟦
16  🟥🟩🟦🟩🟩🟩🟩🟩
VPN не работал ~40 мин.
Провайдер: ~35 мин без интернета.
🟨 мелкий сбой · 🟥 сбой VPN · 🟦 нет интернета · ⬛ нет данных
```

🟩 всё хорошо · 🟨 мелкий сбой (до 10 мин) · 🟥 сбой VPN · 🟦 VPN не работал из-за пропавшего интернета у провайдера ·
⬛ нет данных (роутер был выключен). Данные — почасовая сводка `/root/uptime.log` (хранит 31 день), её раз в час пишет
[uptime-hourly](../mirror/usr/bin/uptime-hourly); рисует [router-day](../mirror/usr/bin/router-day). То же в терминале: `vpn day`, `vpn day 7`.

## Безопасность

- Бот выполняет команды **только из твоего чата** (chat id из настройки). Чужие сообщения молча игнорируются,
  даже если кто-то найдёт бота.
- `/restart` и `/reboot` выполняются только после подтверждения (кнопка ✅ или `/restart_yes` / `/reboot_yes`) в течение 2 минут.
- Кнопки принимаются только из твоего чата и только известные: у каждого запроса своя метка времени, поэтому повторное, старое или
  чужое нажатие даёт «Устарело». Метка проверяется на «только цифры» до использования в арифметике шелла.
- Старые сообщения не выполняются: при запуске бот пропускает всё, что пришло, пока он не работал, и игнорирует
  сообщения старше 2 минут. Иначе `/reboot_yes` выполнился бы снова после перезагрузки.
- Аргумент `/site` проверяется по белому списку символов; динамический текст в ответах экранируется.
- Команды — фиксированный список, произвольные команды шелла бот не выполняет.

## Управление

```sh
vpn tg          # включены ли уведомления, работает ли бот, сколько сообщений ждёт отправки
vpn tg test     # проверочное сообщение
vpn tg off      # выключить уведомления и команды (vpn tg on — включить обратно)
vpn tg setup    # подключить заново (другой бот или другой аккаунт)
logread -e router-bot   # какие команды приходили
```

## Как устроено

- **Уведомления** — `router-notify` из cron раз в минуту. VPN он не проверяет сам: берёт счётчик минут без VPN у
  сторожа sing-box (`/tmp/sb-watchdog/proxy_fail`). Интернет провайдера проверяет пингом мимо sing-box. Перезагрузку
  определяет по смене `boot_id`, а время выключения — по метке «жив», которую раз в 15 минут пишет на флеш.
  Важные события берёт из постоянного журнала автоматики `/root/events.log` по списку `IMPORTANT` в начале скрипта.
- **Команды** — `router-notify --bot` под procd (служба `router-bot`, перезапускается сама, если упадёт).
  Long polling `getUpdates` на 50 секунд, так что отвечает за секунду-две.
- Состояние и очередь — `/root/.notify/`. Пороги (10 мин для VPN, 5 мин для провайдера) — в начале скрипта.
- **Новая команда** — ветка в `bot_run()`, строка в `BOT_HELP` и в `setMyCommands`, функция ответа в `router-tg`. Аргументы
  проверяй по белому списку символов, как в `/site`. Новая кнопка — в `KB` / `MORE_KB` и в `bot()` / `bot_callback()`.
- На роутере `jq` собран без регулярных выражений (`gsub`, `test`, `match` не работают) — вместо них `split` / `join`.

Ограничение: если роутер выключен или полностью завис, он ничего не напишет. Для этого нужен внешний сервис
«пульса» (например, healthchecks.io), который ждёт отметок от роутера и сам пишет, если они пропали.
