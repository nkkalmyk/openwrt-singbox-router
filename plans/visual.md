# План: внешний вид (кнопки в Telegram, «сутки одной строкой», цвета в `vpn`)

Статус на 2026-10-05: **весь план выполнен** (модуль `sb_ui.py`, цвета, `vpn day` и `/day`, `/week`, кнопки в Telegram).
Порядок внедрения: 0 → 3 → 2 → 1 (обоснование в конце).

Отличия сделанного от плана: выбранная сейчас нода жирным со стрелкой не выделяется (лишнее, `auto →` и так
показано сверху); `pretty_text` исключает `/` из тега (как было в router-report). `sb_ui.py` пока без `render_day`
и ANSI-блоков: отрисовка суток осталась в самом `router-day`, потому что нужна только ему.
Шаг 2 по сравнению с планом: самый долгий сбой и перезагрузки в сводке под графиком не считаются (хватает минут
без VPN и у провайдера); неделя — `vpn day 7`, пустые дни до начала истории не показываются.

## 0. Общее: модуль `/usr/lib/sb_ui.py`

Сейчас `pretty()` (имена нод без флагов) скопирован в три места: sb-ping, router-report, sb-route-test.
Вынести в один модуль, его же использовать для цветов и для отрисовки суток:
- `pretty(tag)`, `pretty_text(text)` — как сейчас;
- `color_on()` — включены ли цвета (см. п. 3);
- `paint(text, kind)` — kind: `ok` / `warn` / `bad` / `dim` / `head`;
- `delay_kind(ms)` — <150 → ok, <300 → warn, ≥300 → bad, 0 → dim;
- рисовалки суток (п. 2).
Подключение: `sys.path.insert(0, "/usr/lib"); import sb_ui`. Если модуля нет, скрипт должен работать без
цветов (try/except ImportError → локальные заглушки), чтобы кривая установка не ломала `vpn`.
Добавить в sysupgrade.conf, pull-from-router.sh (FILES), publish.py (mirror/usr/lib/* уже берётся).

## 3. Цвета в `vpn`

**Когда красить:** только если вывод идёт в терминал и не задан `NO_COLOR`. Telegram-бот, cron и `| grep`
получают чистый текст сами собой, ничего отдельно отключать не надо.

**Ловушка:** `vpn status` идёт через трубу `| sb-ping pretty`, поэтому внутри уже не терминал. Решение:
`vpn` один раз в начале проверяет `[ -t 1 ] && [ -z "$NO_COLOR" ]` и экспортирует `VPN_COLOR=1`. Все дочерние
(sb-ping, router-report, router-day) смотрят на `VPN_COLOR`, а если его нет — на `isatty()`. Фильтр `pretty`
ANSI-коды не трогает: регулярка ищет только теги `P1-…`/`P2-…`.

**Палитра:** только базовые 8 цветов (Termius и любой терминал): зелёный 32, жёлтый 33, красный 31,
серый 90, жирный 1. Без белого и чёрного, чтобы читалось и на светлой, и на тёмной теме.
В шелле — переменные `C_OK C_WARN C_BAD C_DIM C_RST` в sb-common.sh (пустые, если цвета выключены).

**Что красим:**
| Где | Что |
|---|---|
| `vpn` (сводка) | OK — зелёным, НЕТ / НЕ РАБОТАЕТ — красным, «выбрана вручную» — жёлтым, заголовки `===` — жирным; в последних событиях — по ключевым словам (ниже) |
| `vpn nodes`, `vpn gemini` | задержка: <150 мс зелёным, <300 жёлтым, ≥300 красным, мёртвые серым; выбранная сейчас нода — жирным со стрелкой |
| `vpn report` | итог «всё хорошо» — зелёным, «были сбои» — жёлтым, «ПРОБЛЕМА СЕЙЧАС» и строки `!` — красным, `~` — жёлтым |
| `vpn log` | красным: откат, перезагрузка, невалидный конфиг, «не запущен»; жёлтым: перетест, обновляю подписки, перезапускаю; зелёным: «снова работает», «Применено, связь есть» |
| `vpn day` | блоки часов (п. 2) |

**Ловушка с выравниванием:** f-string в Python считает escape-коды в ширину. Сначала выравниваем
(`f"{delay:4d}"`), потом красим готовую строку.

**Проверка:** `vpn` в терминале — цветной; `vpn | cat`, `NO_COLOR=1 vpn`, `/status` в Telegram,
`vpn report all` — без единого `\033`. Тест: `vpn status | grep -c $'\033'` → 0.

## 2. «Сутки одной строкой» (`vpn day`, `/day`)

**Данные.** `/tmp/health.log` не годится как источник: он в RAM (пропадает при перезагрузке), без даты, хранит
~41 ч. Поэтому нужен постоянный почасовой журнал `/root/uptime.log`:
```
2026-10-05 14 n=12 vpn_fail=1 inet_fail=0
```
- Пишет его новый cron-скрипт раз в час в :58 (не :07/:37). Он берёт строки health.log за прошедший час
  (по полю HH:MM) и считает: сколько замеров было (`n`), сколько с `proxy=000` и сколько с `direct=000`.
- Хранить 31 день, это 744 строки, ~30 КБ. Пишется на флеш раз в час, это нормально.
- Час, где замеров меньше 12, значит роутер был выключен или перезагружался. Он отмечается по `n`,
  отдельно ничего писать не надо.
- При установке один раз заполнить историю из текущего health.log (~41 ч), чтобы `vpn day` сразу показывал данные.
- Перезагрузки отмечать по `events.log` / boot-меткам router-notify (часы без данных → ⬛).

**Цвет часа (VPN):**
| Значок | Условие |
|---|---|
| 🟩 | все замеры OK |
| 🟨 | 1–2 замера с ошибкой (≤10 мин) |
| 🟥 | ≥3 замера с ошибкой |
| ⬜ | VPN не работал, потому что не было интернета у провайдера (не вина VPN) |
| ⬛ | нет данных: роутер был выключен |
| (пусто) | час ещё не наступил |

Для строки «Интернет» — то же по `inet_fail`.

**Отрисовка в Telegram:** 24 эмодзи в строку на узком телефоне переносятся, поэтому две половины по 12 часов
с подписями:
```
📅 Сегодня, 5 октября
        00 … 11        12 … 23
VPN   🟩🟩🟩🟩🟩🟩🟩🟩🟩🟩🟩🟩  🟩🟨🟩🟩🟩🟩🟥🟩🟩⬜⬜⬜
Сеть  🟩🟩🟩🟩🟩🟩🟩🟩🟩🟩🟩🟩  🟩🟩🟩🟩🟩🟩🟩🟩🟩
VPN не работал ~25 мин, дольше всего — 15 мин в 18:25. Интернет у провайдера — без сбоев. Перезагрузок нет.
```
Это нужно проверить на настоящем телефоне. Если не влезает — по строке на каждую половину суток.

**Отрисовка в терминале:** эмодзи в Termius может не отрисоваться (как флаги), поэтому вместо них блоки `█`
ANSI-цветом. Без цветов — символы: `#` OK, `+` мелкий сбой, `X` сбой, `.` нет данных.
Рисовалка в sb_ui.py: `render_day(rows, style="emoji"|"ansi"|"plain")`.

**Команды:**
- `vpn day` — сегодня и вчера;
- `vpn day 7` — неделя, по строке на день со сводкой, а не 24 квадрата:
  `пн 05.10  🟩 99,6 % — без VPN 6 мин`;
- `/day` и `/week` в Telegram.

**Сводка под графиком:** минуты без VPN (замеры × 5), самый долгий сбой (подряд идущие `proxy=000`; для
сегодняшнего дня берём health.log, он точнее), сбои провайдера, перезагрузки из events.log.

**Проверка:** подложить синтетический uptime.log (все варианты значков, пропуски, начало суток),
сравнить отрисовку; проверить смену суток и пустой файл.

## 1. Кнопки в Telegram

**Постоянная клавиатура под полем ввода** (reply keyboard), отправляется вместе с /start, /help и после
`vpn tg setup`; клиент её запоминает:
```
[📊 Состояние] [🌐 Ноды]
[📅 Сутки]     [📋 Отчёт]
[📜 Журнал]    [⚙️ Ещё]
```
`reply_markup={"keyboard":[…],"resize_keyboard":true,"is_persistent":true}`. Нажатие — это обычное
текстовое сообщение «📊 Состояние». В `bot_run` добавить сопоставление текста кнопки с командой. Слеш-команды
остаются как есть.

**«⚙️ Ещё»** — сообщение с inline-кнопками:
`[🔄 Обновить ноды] [🎯 Автовыбор] [⚡ Скорость]` / `[♻️ Перезапуск sing-box] [⏻ Перезагрузка роутера]`.

**Подтверждение кнопками** вместо `/restart_yes`: сообщение «Перезапустить sing-box?» с кнопками `[✅ Да] [✖️ Отмена]`.
- `callback_data = "yes:restart:<nonce>"`, где nonce — время создания запроса. Он же пишется в
  `/tmp/router-bot.pending`. Принимаем, если nonce совпал и прошло ≤ 120 с.
- После нажатия:
  - `answerCallbackQuery` — убрать «часики» на кнопке;
  - `editMessageText` — заменить вопрос на «Перезапускаю…» и убрать кнопки, чтобы двойное нажатие не
    сработало дважды.
- «Отмена» — то же, текст «Отменено».
- Текстовые `/restart_yes` и `/reboot_yes` оставить для совместимости.

**Изменения в цикле бота:**
- `allowed_updates=["message","callback_query"]`.
- jq выдаёт по каждому обновлению строку TSV: `kind update_id chat date text_or_data callback_id message_id`.
  Для `callback_query` чат берётся из `.callback_query.message.chat.id`, данные — из `.data`.
  Без регулярок: jq на роутере собран без oniguruma.
- **Защита:**
  - чат должен совпадать с `TG_CHAT` (и для кнопок тоже);
  - `callback_data` — только из белого списка действий, `case` по точному значению;
  - правило «сообщения старше 2 мин не выполнять» остаётся для текстовых сообщений; у кнопок вместо него
    проверяется nonce, потому что дата там — дата исходного сообщения;
  - на чужой или просроченный callback всё равно `answerCallbackQuery` с текстом «Устарело», иначе кнопка
    будет крутиться.
- Перед `reboot` подтвердить offset, как сейчас.

**Можно потом:** в «🌐 Ноды» кнопки выбора ноды. Теги длинные, а `callback_data` ≤ 64 байт, поэтому
передавать номер и время снимка списка, а при нажатии проверять, что список не устарел.

**Проверка:** песочница с поддельными `callback_query`, как в прошлый раз:
- чужой чат;
- просроченный nonce;
- двойное нажатие;
- «Отмена»;
- кнопка с неизвестными данными;
- нажатие текста кнопки «📊 Состояние».
Потом живая проверка с телефона пользователя.

## Порядок и почему

0. **sb_ui.py** — фундамент: убирает три копии `pretty()`, на нём строятся цвета и сутки.
3. **Цвета** — самое простое, сразу видно в Termius; заодно отрабатывается правило «красить только в терминал».
2. **Сутки** — сборщик почасовых данных ставить как можно раньше: история копится только с момента установки.
1. **Кнопки** — последними, потому что кнопка «📅 Сутки» уже должна работать.

После каждого шага: песочница → установка через `scp -O` + `chmod` + `sh -n`/`py_compile` (не `cat >`),
обновление docs (runbook, architecture, history, docs/telegram.md в publish), снимок, публикация по просьбе.
